# ADR-0005：提问引擎的优先级与反思插队

- 状态：已采纳
- 日期：2026-10-16

## 背景

产品文档给了四级优先级：昨日缺口与悬而未决项 → 目标追踪 → 精神层反思轮换（每周至少一次）→
随机回顾旧记忆。每晚会话最多 3 个问题。

两个约束会打架：

- 严格按序，优先级 1 和 2 会把 3 个名额吃光，第 3 级的「每周至少一次」永远轮不到；
- 但不按序，就等于取消了优先级。

另外「随机回顾旧记忆」在没有一年以上历史的初期永远轮不到，第 4 级实际上只在有历史之后才生效。

## 决定

1. **优先级 1 最多占 2 个名额**（悬而未决项 1 个 + 缺口 1 个），剩下的名额留给 2–4 级。
2. **反思到期时插在目标前面**。「每周至少一次」是硬约束，它不能被挤掉；目标可以等一晚。
3. 其余严格按序：悬而未决项 → 缺口 → 反思（到期时）→ 目标 → 回顾。
4. 总数由 `questions.session.max_questions` 管，默认 3。
5. 反思是否到期看 `state.json` 的 `last_reflection_date`，间隔 7 天。

## 后果

好处：

- 每晚都有变化：不会连着几周只问「昨天身体怎么样」。
- 精神层每周至少落到一次，这是产品差异化里唯一「无替代品」的部分。
- 一周的反思池只有 5 句，轮换后不会重复。

代价：

- 目标到期且反思也到期的那晚，目标问题被推迟一天。
- `open_markers` 是朴素的子串匹配，会把「计划」这类词在无关句子里也当成待办。
  第一版把标点词收紧到指向未来、可兑现的词（去掉了「要」「想」「等」），误报少了，但仍是启发式。
- 「随机」用了 `Random(today.toordinal())` 做种子，同一天重复调用结果一致，跨天才变。可测，但不是真随机。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 严格按优先级，不插队 | 反思永远轮不到，第 3 级形同虚设 |
| 一次性问完四级 | 每晚十几个问题，没人会答 |
| 让模型直接决定问什么 | 不可复现、不好测，且离线模式下没有模型可用 |
| 反思按固定星期几问 | 与「每晚都要答」的节奏打架，用户会在那天被问两个问题 |
