# ADR-0006：MCP 接入与通知的去处

- 状态：已采纳
- 日期：2026-10-16

## 背景

产品文档把 `server/` 的职责定为「对外暴露 MCP 与 REST API，AI 与面板统一接入」，M2 的验收是
「向外部 AI 问『我上周的运动和情绪有什么关系』，回答能指回具体记录」。接入协议选的是
`modelcontextprotocol` 的 python-sdk。

同一批事里还有两处「绑死平台」的隐患：

- 通知只在 macOS 走 `osascript`，其他平台打到 stdout——「每晚被提醒」这件事在 Linux 上等于没有；
- 采集与回顾都默认用户坐在同一台机器前，别的设备、别的进程拿不到大脑。

## 决定

### MCP

1. **用官方 python-sdk**，自己不去拼 JSON-RPC。版本约束 `mcp>=2.3,<3`。SDK 只在真跑
   `pkbrain mcp` 时导入，`pkbrain search` 之类的日常命令不为它买单。
2. **两种传输都给**：`stdio`（本地客户端，默认）与 `streamable-http`（别的机器、别的进程）。
   平台与客户端都不锁死。
3. **工具面八个**，先把手动闭环里已有的能力透出去，不新做能力：

   | 工具 | 读写 | 说明 |
   |---|---|---|
   | `brain_schema` | 只读 | 维度、指标、隐私分级、通道——写之前先看它 |
   | `brain_stats` | 只读 | 条数、覆盖天数、完整率、连续天数 |
   | `search_records` | 只读 | 全文检索，可按维度 / 日期 / 隐私过滤 |
   | `get_record` | 只读 | 按日期或 id 取 Markdown 原文 |
   | `metric_series` | 只读 | 某指标随时间的取值 |
   | `list_goals` | 只读 | 目标清单 |
   | `todays_questions` | 只读 | 今天会问什么，**不动状态、不写记录** |
   | `add_record` | 写入 | 一段文本落成记录，`channel=chat`、`source=mcp` |

4. **写入可以关掉**：`[mcp] allow_write = false` 得到一个只读大脑。默认开，因为 M2 的验收
   写的是「MCP 读写」。
5. **参数错了回一句人话**，不抛裸异常。客户端只看到 `Error executing tool` 对谁都没用。
6. **隐私不靠猜**：记录带的三级隐私原样暴露给客户端，指令里写明「P2 是用户特意标成敏感的，
   往外发之前先问一句」。真正的隔离（P2 静态加密）还没做，见 PKBS-MIN 的已知限制。

### 通知

7. **去处是配置，不是代码分支**：`[notify] backend` 取 `auto / macos / linux / command / stdout / none`。
   `auto` 在 macOS 用 `osascript`，有 `notify-send` 就用它，都没有才打到终端。
8. **`command` 就是 hook**：一条 shell 命令，`{title}` 与 `{message}` 会被替换，同时以
   `PKBRAIN_TITLE` / `PKBRAIN_MESSAGE` 传给子进程。接 Bark、ntfy、企业微信、写文件都不改代码。
9. **发不出去不算失败**：投递返回 `Delivery(delivered, backend, detail)`，`serve` 不因此中断。
10. `pkbrain notify "文本"` 是自查入口：配完 hook 先发一条看看通不通。
11. `schedule.notify` 仍是「到点发不发」的开关，与去处分开。

## 后果

好处：

- 任何 MCP 客户端接上就能问，不用为每个 AI 写一遍适配；
- 「问我的历史」有据可查：检索结果带日期、id、隐私分级，回答能指回去；
- 平台不再是前提。Linux 上用 `notify-send`，服务器上用 hook 推一条消息；
- `todays_questions` 把提问引擎也交给了外部 agent，而它仍然是只读的——不会因为被外部
  调用一次就吃掉今晚的轮换状态。

代价：

- **依赖变重**：`mcp` 会拉进 starlette、uvicorn、cryptography 等二十来个包。本地优先的
  CLI 装出一棵这么大的依赖树不理想，但自己实现协议要跟着规范走，成本更高。折中是只在
  `pkbrain mcp` 时才 import。
- **写入面是有风险的**：`add_record` 让 agent 能往知识库里写字。默认开是为了对齐 M2 的
  「读写」，但它是这台机器上唯一接受外部写入的入口，关掉它就退回只读。
- **hook 是任意命令**：`command` 会被 `sh -c` 执行。这与 git hook 同性质——配置是用户自己的，
  但发出去的 config.toml 等于把执行权交出去，分享前要看清。
- MCP 只给本地，**没有认证**。`streamable-http` 默认只监听 `127.0.0.1`；要对外听，得自己想
  清楚网络边界。
- REST（`/records`、`/search`、`/metrics`）仍未做。产品文档写了，但 MCP 已经覆盖了
  「AI 接入」这个目的，REST 留到回顾面板需要时再说。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 自己实现 JSON-RPC 与 stdio 帧 | 协议在动，省下的依赖不值这份维护成本 |
| 只做 stdio | 「不限制平台」要求能跨进程、跨设备接 |
| 只做 MCP，工具面把写入也省掉 | 与 M2 的「MCP 读写」不符；agent 顺手记一条是最自然的用法 |
| 通知继续写死在 `osascript` 上 | 产品文档只是「Build in Public」，用户不都在 macOS |
| 通知接一个消息队列 / 内建 webhook | 一件事引一个依赖。一条 shell 命令能到的地方，就不该再加一层 |
