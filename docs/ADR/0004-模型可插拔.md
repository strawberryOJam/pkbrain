# ADR-0004：模型可插拔，默认离线

- 状态：已采纳
- 日期：2026-10-16

## 背景

每晚的会话要用模型做两件事：把选出的问题改写成一句自然的问句，以及会话结束时回应一句。

这带来三个约束：

1. 产品原则是本地优先、默认不出网，而调用云端模型要出网；
2. 用户可能没有 API key，也可能不想为每日记录付费；
3. 记录里要留下 `model` 与 `tokens`，用于成本观察与可复现审计。

## 决定

定义 `brain.llm.LLM` 协议，两个实现，由 `config.toml` 的 `llm.provider` 选择：

- **`template`（默认）**：不联网、不要密钥。问句直接用 `schema/pkbs.yaml` 里的话术原文。
- **`openai`**：任何 OpenAI 兼容端点。Ollama 填 `http://localhost:11434/v1`，不需要 key；
  DeepSeek、OpenAI、豆包填各自的 `base_url` 与 `api_key_env`。

密钥只从环境变量读，不写进配置文件，也不进记录。调用失败一律回退到模板话术。

## 后果

好处：

- 装完就能用，零成本、零配置、不出网。第一条记录不需要先申请 key。
- 数据里带着 `model` 和 `prompt_used`，将来换模型能对比同一批输入的不同产出。
- 网络抖动不会让晚上的会话开不起来——失败就退回模板句。

代价：

- 默认的问句是预先写死的，不如模型改写过的贴合昨天的事。
- 抽取仍是规则。模型只参与措辞，不参与结构化——语义抽取（人物、事件、情绪词）还没有。这是 M2 的事。
- 只实现了 OpenAI 兼容协议。用别的协议要自己加实现，不过协议本身很小（两个方法）。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 只支持云端 API | 违背本地优先；没 key 的人第一天就跑不动 |
| 只支持本地 Ollama | 需要用户先装 Ollama 再拉几个 GB 的模型，第一次体验太重 |
| 引 LangChain 之类的抽象层 | 为了两个方法引入一层框架，依赖和不确定性都不划算 |
| 硬编码一个云端模型 | 与「可插拔」的定位直接冲突 |
